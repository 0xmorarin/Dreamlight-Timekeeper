# Image and accessible UI icon contract

## Owner decision (2026-11-01)

Images deliberately use two distinct formats:

| Kind | Namespace | Format | Source |
| --- | --- | --- | --- |
| Item images | ItemID | VP8L Lossless WebP | Verified original Steam game assets |
| Game-specific UI/world icons | `game_ui:<semantic.key>` | VP8L Lossless WebP | Verified original Steam game assets |
| Tool controls and state glyphs | `app_ui:<semantic.key>` | SVG | Original, tool-specific SVGs drawn and maintained within this project |

The older all-Lossless-WebP policy **does not apply to app_ui**. Do not convert these original app SVGs back into raster assets. Game-source images must never be substituted with a newly drawn vector that merely resembles the game.

## App SVG — provisional owner-created artwork and accessibility

**Owner decision (2026-11-01): use the original, project-authored SVG set provisionally.** Fine visual tuning belongs to the final UI polish phase, not the present save-analysis implementation phase. Third-party icon sets are reference material only and are **not** shipped or depended upon. The prior temporary Lucide selection was superseded; `vendor/lucide/`, its upstream license files, and Lucide-source mappings have been removed from the active branch tree. Historical Git commits may still retain them, but release contents must not.

Exactly 16 original geometric glyphs are defined in `src/app-ui-icon-design.mjs` and deterministically generated by `scripts/build-app-ui-icons.mjs`; no third-party icon package, icon font, remote provider, or runtime CDN is needed. The generated 24×24 SVGs share neutral `#f2f6f6` strokes, a 2.25-unit width, rounded caps and rounded joins. The `data/app-ui-icons.json` revision 2 manifest sets `designStatus=PROVISIONAL_OWNER_ARTWORK` to distinguish visual acceptance from asset-integrity verification and retains SHA-256 for each original shape definition and final shipped SVG, semantic key, and project source path. Verify that the build reproduces every SVG byte-for-byte.

The current 16 conceptual keys are `action.open-save`, `action.open-another`, `action.backup`, `action.search`, `action.filter`, `action.expand`, `action.collapse`, `action.calendar`, `action.clock`, `action.utc`, `action.local-time`, `action.technical-details`, `status.warning`, `status.error`, `status.success`, and `status.missing-asset`. In the present browser UI only six app UI glyphs are referenced: `action.open-save`, `action.open-another`, `action.backup`, `action.search`, `action.clock`, `action.technical-details`. Registering a glyph is not proof of use or need in the screen.

**Universal design constraints:** text labels and translated tooltips remain visible; decorative icons use `alt=""` and `aria-hidden="true"`; keep focus indication, sufficient foreground contrast and touch targets of at least 44px. Do not rely on shape or color alone to communicate a diagnostic finding. Missing images must not break read-only controls, file selection, keyboard access or a fallback status message.

**Final polish checklist, deferred:** compare each visible icon at 16, 20 and 24px, across light and dark surfaces and browser zoom 200%; adjust optical alignment, line density, negative space, touch/click target, contrast, and semantic recognizability. Check Japanese/English with SVG missing. Unused prospective glyphs should be reviewed before public release rather than modified speculatively. There is **no current permission** to rasterize tool SVGs or to replace game-source assets with self-drawn symbols.

The app manifest permits only local `.svg` paths and its validator restricts the exact geometric root, static shape types, attributes, original-source hashes, path and dimensions. Both UI namespaces require a registered semantic key and its exact canonical local path (`<namespace>/<category>/<name>.<format>`); missing keys, including inherited object properties, resolve to null. The SVG parser must consume every shape attribute and reject unparsed mixed-case or namespaced attributes rather than silently ignoring them. Scripts, remote image sources, external references, SVG animation and arbitrary HTML are not allowed.

## Resolution and verification

`resolveIconAsset(itemManifest,itemId)` remains numeric. `resolveGameUiIcon(gameUiManifest,key)` only uses the original-versioned WebP manifest, while `resolveAppUiIcon(appUiManifest,key)` only uses original SVG metadata. The same UI function may use both resolvers, but neither can fall through into the wrong asset namespace. Both return null on invalid or missing provenance. No icon affects gameplay or save-field policy.

`npm test` checks names, manifests, security restrictions and byte integrity; `npm run test:icon-import` exercises a fully staged site with both game-source and app-source assets. The Chromium smoke workflow checks downloaded image decoding, language re-rendering, synthetic encrypted P1g read-only load, warning icon display, mobile layout, and fallback if an icon request is blocked. This does **not** authorize writing an edited save, and is not equivalent to actual Switch runtime acceptance.

The product remains four-tab and read-only. Special 2126 values, timestamp editing targets and restore logic remain provisional, independently gated by the original save-timing research contract.
