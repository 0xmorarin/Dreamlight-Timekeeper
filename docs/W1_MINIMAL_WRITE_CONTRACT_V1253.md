# Minimal W1 NextOccurrence target contract — Switch v1.25.3 / schema626

**Ownership:** 02 TIME defines source/Native target eligibility; 01 CORE owns codec, original snapshot, exact-field delta and any future write gate; 05 QR owns independent acceptance. **Status: SYNTHETIC_TESTED structural target identification only; no enabled Writer or edited export.**

## Operation

The **only** researched mutation shape is an existing JSON value at:

`World.RecurringEvents/<index>/<Variant>/NextOccurrence`

Represented by canonical JSON Pointer `/World/RecurringEvents/<index>/<Variant>/NextOccurrence`.

Allowed variants are **only** `ItemSpawning`, `WildCropsSpawningInVillage`, `FlowerSpawningInVillage`, `FishSpawningInVillage`. No insert, deletion, grid/object mutation, last-occurrence change, inventory or ownership change is within this contract. The JSON container is the save's **existing** `World.RecurringEvents` object; index is a canonical decimal map key, not a source Event ID. In a proposed target, these independent identifiers are maintained: `eventId`, `savedIndex`, `variant`, `pointer`, `linkedItemIds`, `originalTime`, `targetTime`.

The same source registry has **508 event definitions** in v1.25.3 (BID `9A239D3DB569756D`, schema626, source SHA256 `028a206635d37bffd7f3a8ff820958bdaa201887bacf35e10faa8328d20022ea`). A source EventID is **not** an ItemID, GridObject.ID, source-list position or guaranteed per-save oneof. Registry W1 policy and the existing `compileW1NativeSemantics` source-family hint narrow candidates but are **not** Native instance proof.

## CORE integration API

Use `assessMinimalW1WriteTargets(profile, snapshot, plan, registry, nativeLedger)` from `src/w1-minimal-write-contract.mjs`. The `snapshot` is the **Worker-owned**, same-session output of `assessTimingSnapshot(projectProfile(...), indexTimingReviewRules(...))`; `plan` is an array of `{pointer,originalTime,targetTime}`. The registry is the exact packaged `data/events-v1253.json`; `nativeLedger` is generated by existing `compileW1NativeSemantics(registry,{woodTagPack})` using the independently verified Wand isWood crosswalk. Reuse the existing `inspectTimingPlan` structural/original-value preflight; no UI-supplied event eligibility flags or source-build claims are trusted.

The function returns a frozen result containing:

- `status`: `STRUCTURAL_W1_TARGETS_ONLY` or `BLOCKED_W1_WRITE_TARGETS`.
- `rows[]`: one diagnostic per plan pointer, with `code`, exact `eventId`, `savedIndex`, `variant`, `linkedItemIds`, original/target timestamp and structural eligibility.
- `candidateTargets[]`: exact candidate triples and paired timestamps **only if every planned row passes**. If any row fails, the entire candidate list is empty.
- `authorizedMutationPaths: []`, `writerAuthorized:false`, `editedExportAuthorized:false`, `exportAvailable:false`, `sourceMutationPerformed:false` at **all** times.

A candidate is **a validated path for a future CORE operation**, not permission to modify or serialize a profile. To unlock a product Writer would require separately approved, version-specific 01 CORE serialization/provenance/diff/encode/reopen and 05 QR plus required hardware acceptance. This module must never be treated as the sole authorization decision.

## Fail-closed rules

The contract rejects the entire batch's candidate list when any field:

1. Is not exactly an existing `World.RecurringEvents/<canonicalDecimalIndex>/<oneAllowedVariant>/NextOccurrence` pointer, has an unsafe/duplicate pointer or no original value, changes the original value since snapshot, supplies an invalid UTC target or proposes no change.
2. Has a profile/schema identity other than `GameInfo.Version=626` with a matching snapshot `identity.schema=626`; source metadata and reviewed research provenance must match v1.25.3/BID `9A239D3DB569756D`. A save schema does **not** independently prove an executable BID.
3. Contains multiple oneof branches or an extra unknown container key (including an otherwise empty object), lacks a target variant or has inconsistent `RecurringEventItemID`/pointer/index/save row. The same stored EventID appearing more than once in saved recurring entries is also refused.
4. Has a missing source definition, duplicate definition ID, mismatch between the 508 source inventory and Native ledger, wrong source-family variant hint, altered linked ItemIDs, inactive/unknown source activity, non-W1 policy or forged source row.
5. Is protected: **Moonstone Chest `2010000064`**, TimeBending HOLD `2010000093` and `2010000120`, W2 Snippet, quest/other HOLD, any inactive Fish event, unknown/unsupported variant or schema.

**Date policy:** a valid intentionally far-future time, including `2126-08-20T00:00:00Z`, is permitted as a proposed original/target value and is not automatically classified as corruption. The ordinary Native execution, Client scheduler, configured area limits, amount/AssignedPlayer, existing GridObjects, ConditionalEvent references and item recovery semantics are not claimed to be runtime verified by that structural acceptance.

## Owner observation and remaining evidence

The Owner reports observing automatic spawn suppression after intentionally setting `NextOccurrence` far into the future. The contract preserves this **only** as aggregate `OWNER_REPORTED_RUNTIME_CONFIRMED` with `exactEventIdsConfirmed:[]`, `eventIdSpecificRuntimeAuthorization:false`, `extensionToAllW1VariantsPermitted:false`, and `independentQRAcceptance:false`. It is **not** `RUNTIME_TESTED` for each source ID, nor a claim that source build/schema of that observed save is independently proven.

Native static research (Round 1–10) established W1 `NextOccurrence` setter field and scheduler conditions, but not an EventID-specific game runtime replay, writer success or game-save cold load. All **46** v1.25.3 fish ripple source definitions are inactive and remain excluded, even though the Fish oneof is structurally within the four W1 families.

## Tests and safe handoff

`tests/w1-minimal-write-contract.test.mjs` uses the exact packaged 508 definitions, native ledger and synthetic profiles to test three active variants, invalid and stale UTC values, far-future valid values, mixed-batch atomic hold, inactive Fish, Moonstone, TimeBending, W2, schema drift, duplicate saved IDs, parallel unknown oneof branches, forged pointers, altered ItemID mappings, untrusted source/Native metadata and original immutability. No physical Switch runtime or edited save was generated.

**01 CORE contract:** consume `candidateTargets[]` for **planning only**, revalidate inside the Worker on the current original profile before any future transaction and never use it as a write allowlist until the independent Writer release gates pass. Any future Writer may change only those original values, must perform exact delta verification and independent encode/reopen, and must never override original saves. No direct source-file overwrite. No ZIP bundled distribution.
